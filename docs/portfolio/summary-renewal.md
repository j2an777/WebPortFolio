# 소개 Summary와 Purple Academy 콘텐츠 개편

기준일: 2026-10-19. 사용자와 합의한 다섯 축을 같은 순서로 반영했다.

1. 인증·결제 실패 추적과 복구
2. 중복 조회 제거와 데이터 성격별 캐시
3. 개발·운영 작업의 도구화와 재사용
4. 웹·앱 경계의 사용자 흐름
5. 개인정보·인증 정보 노출 경로 축소

`expertise`를 홈·Expertise·웹 이력서·포트폴리오 PDF의 원문으로 공유한다. 이력서 PDF에는 같은 다섯 제목을 싣고, 웹 이력서에서 설명을 제공한다. 기존 경력 수치와 측정 조건은 유지했다.

## 내용의 근거와 범위

Obsidian develop-note의 cases 18편과 guides 2편을 비교한 뒤, 결제·인증·성능·운영 자립화·공유 AI 스킬·웹뷰·GA4 기록을 활용했다. 공개 상세에는 관련 Velog 글과 기존 PR 근거를 연결했다. 회사 원문 코드나 비공개 운영 자료는 추가하지 않았다.

- 결제 이관의 서버 상태 전이는 동료 구현임을 명시하고, 본인의 재시도·재확인·중복 확정 방지 작업을 구분했다.
- HttpOnly·BFF를 XSS 자체 차단으로 표현하지 않는다. JavaScript의 토큰 접근 제한과 개인정보 전송 경로 개선을 설명한다.
- 어드민 Origin 검증으로 범위를 한정한다. 전체 서비스의 출처 검증이 통일됐다고 주장하지 않는다.
- DB 왕복 감소는 코드 경로 비교다. 기존 핵심 쿼리 767ms를 전체 API의 전후 성능 수치로 바꾸지 않았다.
- 공유 스킬 자동 갱신·검사 구축과 팀 전체 생산성 개선율을 구분한다.
- 앱 빌드·스토어 업로드와 심사 제출·공개 출시를 구분한다. ASO 설치 증가를 성과로 주장하지 않는다.

## 검증

- ESLint, TypeScript, 기존 소스 테스트 11건, Next.js 프로덕션 빌드 통과.
- 이력서 Playwright 6건 통과: 320·390·768·1440px, PDF 다운로드, 접근성, JavaScript 비활성.
- 390·1440px에서 Summary 5개와 Purple Academy 상세의 가로 넘침 없음 확인.
- 이력서 PDF 3페이지 생성·넘침 검사, 변경된 1페이지와 3페이지 시각 확인. 포트폴리오 PDF 첫 장의 Summary 5개 배치 확인.
- Windows에서 npm test의 와일드카드가 확장되지 않아 PowerShell로 파일 목록을 전달해 동일 테스트를 실행했다.
- PDF·검증 캡처·이전 콘텐츠 스냅샷은 기존 정책에 따라 로컬 output과 public의 gitignore 대상에 보관한다. 배포 워크플로가 PDF를 재생성한다.
