## 목표와 독자

하승진의 개인 포트폴리오를 기존 HTML·jQuery 프로젝트에서 Next.js App Router + TypeScript + Tailwind CSS + GSAP 기반으로 리뉴얼한다. 채용 담당자와 동료 개발자가 소개, 실무 기여, 문제 해결 과정, 프로젝트 화면, 연락 방법을 빠르게 찾을 수 있어야 한다.

사용자가 위임한 범위는 콘텐츠 분석, UI 콘셉트 선택, 필요한 의존성 추가, SEO·AEO, 디자인 시스템, 재사용 유틸·훅, LCP 최적화, 서버 렌더링, 애니메이션과 디자인 패턴 구현이다. 추가 요청인 프로필 사진과 프로젝트별 썸네일을 필수 요구사항으로 포함한다. 구현 이후 저장소 소유자 `j2an777`로 인증하고 리뉴얼 브랜치를 원격에 push했다. 운영 배포는 별도 단계다.

## 디자인 시스템

- 색상: paper `#F4F2ED`, ink `#191919`, muted `#66645F`, accent `#E6532F`, line `#D8D5CE`.
- 의미 기반 토큰: background, foreground, muted, accent, border, surface, focus.
- 타이포그래피: 영문 display와 한국어 body를 분리하고 로컬 WOFF2로 서빙한다. 폰트 라이선스를 저장한다. 필요한 굵기만 사용한다.
- 간격: 4px 기반 스케일. 모바일 20px, 태블릿 32px, 데스크톱 48~64px 좌우 여백.
- 최대 콘텐츠 폭 약 1280px. 큰 제목은 `clamp()`로 반응형 처리한다.
- 기본 패턴: Container, SectionHeading, TextLink, Tag, ProjectCard, ProjectFigure, MetadataList, EvidenceLink.
- 버튼과 링크는 동작에 맞는 HTML 태그를 쓰고 변형·크기를 타입으로 관리한다.
- 긴 제목·긴 기술명·이미지 없음·키보드 탐색·320px 폭에서 레이아웃을 확인한다.

## 렌더링과 코드 구조

콘텐츠는 타입이 지정된 로컬 데이터로 관리하고 브라우저에서 GitHub·Notion에 실시간 접속하지 않는다. 토큰과 개인 정보 없이 배포 가능한 구조로 만든다.

```text
src/app/                  # 홈·상세·메타데이터·robots·sitemap·OG
src/components/ui/        # 실제 반복되는 UI
src/components/sections/  # 홈 섹션
src/components/motion/    # GSAP 클라이언트 경계
src/content/              # 프로필·프로젝트·경력·개선 사례 데이터
src/hooks/                # 공통 모션 훅 등 실제 사용처가 있는 훅
src/lib/                  # URL·메타데이터·JSON-LD·콘텐츠 조회 유틸
public/images/            # 최적화한 프로필·프로젝트 자산
docs/                     # 근거·디자인 시스템·검증·배포 안내
```

서버 컴포넌트가 모든 본문·링크·이미지를 렌더링한다. 서버 HTML에 콘텐츠가 있어야 하고 JavaScript를 끈 상태에서도 탐색과 상세 읽기가 가능해야 한다. 변경 빈도가 낮은 홈과 상세는 빌드 시 사전 렌더링을 우선한다. SSR과 SSG는 모두 서버에서 HTML을 만들지만, 요청마다 실행되는 SSR로 모든 페이지를 강제하지 않는다. 요청 시 데이터가 필요한 기능이 생길 때 해당 경로만 동적으로 렌더링한다.

클라이언트 경계는 모션과 필요한 상호작용에만 둔다. React Query·Zustand 등 런타임 상태 라이브러리는 정적인 포트폴리오에 실제 필요가 확인되기 전까지 추가하지 않는다.

재사용은 실제 반복을 기준으로 한다. 공통 JSON-LD 안전 직렬화, 메타데이터 생성, 프로젝트 조회, `cn()` 유틸, GSAP lifecycle 훅을 고려한다. 한 번만 쓰는 코드까지 범용 프레임워크로 만들지 않는다.

## 모션

- GSAP `matchMedia()`로 reduced motion을 분기하고, 스크롤 reveal·이미지 parallax를 경로마다 정리한다.
- 메뉴 이동은 세 패널이 화면을 덮은 뒤 경로를 바꾸고 열리는 전환을 제공한다. 수정키·외부 링크·앵커·모션 감소는 표준 탐색을 유지한다. 뒤로 가기는 전환을 취소한다.
- 섹션 진입의 작은 이동, 이미지 reveal, 프로젝트 hover, 프로젝트 이미지의 제한된 parallax를 사용한다.
- ScrollTrigger와 GSAP context는 컴포넌트 해제 시 정리한다.
- 히어로의 LCP 텍스트와 프로필 사진을 opacity 0으로 숨기지 않는다.
- 스크롤을 가로채지 않으며 키보드·터치에서 hover 없이 사용할 수 있어야 한다.
- reduced motion에서 이동·스크롤 연동 모션을 해제하고 모든 내용을 그대로 보여 준다.
- 모션 코드 로딩 실패 시에도 본문이 남는 progressive enhancement로 설계한다.

## SEO·AEO

- 페이지별 title, description, canonical, Open Graph, X 카드와 실제 이미지 설정.
- `Person`, `ProfilePage`, `WebSite`, 상세의 `CreativeWork`·`BreadcrumbList`를 실제 페이지와 일치시킨다.
- JSON-LD는 `<` 등을 안전하게 escape하여 script 탈출을 막는다.
- 프로젝트의 설명·기여·결과는 서버 HTML에 짧고 독립적으로 이해되는 문장으로 작성한다.
- robots·sitemap·`llms.txt`를 같은 사이트 설정과 콘텐츠에서 생성한다.
- 최종 origin은 `SITE_URL`로 지정한다. 기존 GitHub Pages 주소를 Next SSR의 배포 주소라고 가정하지 않는다.
- 검토용 배포는 `noindex`, 확정된 운영 주소는 `index`로 설정한다.
- 포트폴리오 FAQ를 Google의 FAQ rich result 보장으로 설명하지 않는다. `llms.txt`도 AI 인용·순위 보장으로 설명하지 않는다.

## 이미지와 성능

프로필 원본은 Notion의 `profile.png`; 개인 프로젝트 원본은 Dart `Mock Up.png`, MemoLinx `Frame 28.png`이다. 만료되는 Notion URL을 런타임에서 쓰지 않고 로컬 자산으로 가져온다. 회사 브랜드 이미지는 `purple-portfolio/screenshots/`의 화면 캡처를 사용한다. 관리자·학생 개인정보가 들어 있는 화면은 공개하지 않는다.

Next Image로 width·height 또는 고정 aspect ratio, 정확한 `sizes`를 지정한다. 첫 화면 프로필만 우선 로딩 대상으로 정하고 하단 프로젝트는 lazy loading한다. WebP/AVIF 등으로 출력하되 화질과 실제 다운로드 크기를 확인한다. 이미지 alt는 프로젝트 이름과 화면의 내용을 설명한다.

로컬 모바일 Lighthouse 목표: performance 90 이상, LCP 2.5초 이하, CLS 0.1 이하. 목표는 측정 전 성과로 쓰지 않는다. 로컬 실험실 수치는 배포 후 실제 사용자 CWV와 구분한다. INP는 실제 사용자 관측이 필요한 항목으로 문서화한다.

## PDF 검토 후 추가된 채용 관점의 편집 원칙

2025 입사 포트폴리오 PDF는 23페이지 전체의 텍스트와 렌더링 화면을 확인했다. 실제 프로젝트 이미지와 예시 이미지, 과거의 구현 방식과 현재의 개선 경험을 구분한다.
